# Independent normalized-bulk limma component

This standalone component uses official `limma::lmFit` and
`limma::eBayes(trend=TRUE, robust=TRUE)` for already normalized log2 expression.
It neither replaces nor modifies the raw-count/voom `cachexia-limma` adapter.
It makes no new normalization, integration, probe collapse, program selection or
per-contrast FDR correction. Existing source eligibility, method/distribution
acceptance, protected image/runtime qualification and scientific G0 stay separate.
There is no image or resident-node registration claim in this directory.

The component accepts a strict thirteen-field frozen template from
`research_b_bulk_limma_inputs.py`, with four actual bound input hashes:
expression, genes, samples and decisions. It measures the declared R, limma,
statmod, jsonlite, digest and stats versions before either stage. Null/unbound
hashes, transformed-count substitution, formula/covariate ambiguity, repeated
units, factor-level loss, missing values and input drift are refused. The
component preserves original gene order and all sample decisions. Source patient
keys and biological independence are declarations, never certified here.

`run-design.R` is a fixed five-input/one-output entry: config, expression, genes,
samples, decisions → audit.json. It constructs only the declared metadata design;
it reports sample/unit identities, group counts, rank, residual df and candidate
family eligibility, without fitting gene expression.

`run-limma.R` is a fixed six-input/three-output entry: those same five inputs plus
the actual same-source DESIGN audit → results.tsv, audit.json, official.rds.
The actual QA/config/input/software/design identities must match. The fixed
entries embed the component source and are generated by
`scripts/build_b_bulk_limma_wrappers.py`; they read only declared ports.
The eventual runtime preparation helper must consume all nine actual sources:
original ZIP, preparation request and the seven raw inputs. A seven-input helper
that reads a ZIP/request from the host or environment is not acceptable.

Each result retains the six gene registry fields plus status/reason, numerator/
denominator, raw_p/family_p/family_p_status/family_p_reason, log2_expression_difference,
standard_error/ci_lower/ci_upper, moderated_t/moderated_df, average_expression and
n_case/n_control. The confidence interval uses official moderated variance and
degrees of freedom. Constant genes retain NA rows. Two-unit groups may have raw
exploratory estimates, but keep family P unavailable under the frozen minimum
of at least three. One-unit groups retain the whole descriptive family without
fitting. A rank-deficient design or nonpositive residual df returns
NOT_ESTIMABLE_DESIGN with DESIGN_NOT_IDENTIFIABLE and complete NA rows, without
fitting. Malformed identities, missing covariates and invalid schemas still
block processing. The
complete multi-contrast BH/BY family and conservative NA→1 correction placeholder
belong to a separate complete-family stage. No topTable filtering is used.

Audit scope is `BULK_NORMALIZED_MODEL_COMPONENT_NOT_G0_OR_SCIENTIFIC_ACCEPTANCE`;
stage is DESIGN or LIMMA. Each audit binds config/input/software/design and the
model formula. LIMMA additionally binds the actual DESIGN audit and all official
warnings. formal_authorized/scientific_approval_verified/biological_independence_verified/
source_qualified/family_frozen remain false. The official RDS retains the fitted
limma object, variable gene IDs and the complete gene IDs. All output publication
refuses overwrite; fixed-port publication removes its own partial links on error.

The tiny permanent transport fixture under
`crates/node-bundles/nodes-io/test-data/b-bulk-limma-transport/` contains 25 fully
synthetic features and explicit complete (4vs4), low-precision (2vs4),
descriptive (1vs4), below-threshold (3vs4, family threshold 4) and rank-deficient
(4vs4, constant age) scenarios. It binds actual config/template, results, method and
DESIGN audits, genes, samples, all ten original sample decisions and the original
expression input. The final-original resource ID is only a registry slot for
engineering declarations, never evidence of real GSE acquisition or source
membership. generation-receipt.json names actual official component versions and
hashes, and explicitly denies real source, image, worker and scientific/G0 scope.

Local host component tests require an explicit existing official library:

```sh
BMC_BULK_LIMMA_R_LIBRARY=/path/to/measured/R_library \
  PYTHONPATH=scripts:scripts/tests \
  python -B -m unittest test_b_bulk_limma_official -v
python -B -m unittest discover -s scripts/tests -p test_b_bulk_transport_fixture.py -v
```

The synthetic tests compare all adjusted gene coefficients with an independent
pivoted Python least-squares solve, verify complete constant/unavailable rows and
CI ordering, check actual fixed ports, and reject altered QA/protocol/scale/method
and non-boolean parameter declarations. They are host component evidence only.
Actual GSE130563 inputs have undergone technical preparation but have not been
fitted by this component. GB01 and the rest of the actual admission must remain
fail-closed until the responsible scientific/source reviewers sign.

Official method reference: [limma manual](https://bioconductor.org/packages/release/bioc/manuals/limma/man/limma.pdf).
