# C risk evidence matrix

`c_safety_declared_risk_matrix` builds the complete declared candidate × seven
normal-tissue risk domains from the v4.2.1 design. It preserves the sole
candidate ledger, intended intervention scopes and full curated evidence table.
It emits a descriptive matrix and a content/software audit. It does not perform
statistical tests or approve candidates, sources, methods, safety or treatment.

The five file ports are the exact JSON declaration, original design ZIP, complete
candidate ledger with the original `CANDIDATE_BRIDGE_REGISTER.tsv` columns,
candidate scopes and curated evidence. The JSON declaration names every source
SHA256 and byte size, exact software lock, seven risk domains, complete-input
resource bounds, protocol `4.2.1`, family `C_SAFETY` and status
`RISK_MATRIX_DECLARED_NOT_ADMITTED`. `scripts/research_c_safety_matrix.py` defines
the exact schema. No executable code comes from the input files.

`c_safety_bound_risk_matrix` is the separate six-port entry for attachment to a
C network DAG. It takes the same five sources plus the canonical original network
preparation as port 5, and requires declaration schema version 2. That preparation
must bind the exact candidate ledger, original design archive and complete network
family. `scripts/research_c_safety_dag.py` attaches the node without changing the
network family or gates; the five risk outputs remain descriptive sealed
attachments, not statistical family tables.

Protected native admission rejects the unbound entry. For the bound entry it
checks the actual source references, candidate/scopes census, frozen network
template, source preparation, seeds, universe, normalized graph identities and
job coordinates. Tests of the compiler, fixed entry and native admission establish
those contracts only. The complete protected network-plus-risk DAG still requires
its own actual worker and container execution qualification; existing standalone
matrix or network qualifications do not substitute for it.

The operator test fixture can explicitly select `--with-risk` in
`scripts/tests/prepare_c_network_protected_fixture.py`. It keeps the complete
20,000-gene, 256-test network scope and uses its sole synthetic candidate ledger
for all seven risk domains. The resulting 19-node DAG has 15 admitted source
files and three fixed container producers. The matching ignored Rust operator
test is `prepare_synthetic_c_network_risk_worker_deployment_fixture`; its
`RESEARCH_SYNTHETIC_C_NETWORK_RISK_*` inputs and test authority are explicitly
restricted to `SYNTHETIC-ENGINE-TEST`. This fixture never enrolls the original
study, alters an original G0 gate or supplies scientific method approval.

Each candidate has exactly one declared scope containing intended intervention
direction, species, tissue, dose, time and life stage. All candidates occur in all
seven risk domains. Missing evidence yields `NOT_ASSESSED`; every safety
conclusion remains `NOT_DETERMINED`. Matching requires all six scope fields to
be known and exactly equal. Differing or unknown contexts and opposite directions
are retained separately. Reported harm and reported absence of detectable harm
remain visible together; absence of evidence is never a safety conclusion.

Curated evidence rows identify database/release, primary source and asserted
lineage. Mirrored source assertions retain one descriptive lineage count, while
the original records remain intact. Lineage counts are not independent biological
replicates. Contradictory assertions for the same primary source, candidate,
domain, evidence type and context fail instead of selecting the favourable row.
Different experiments or different contexts can report conflicting outcomes and
remain visible. The node verifies the bytes of the curated table; it does not
verify the original publication, database query or biological assertions.

Full input consumption and whole-bundle publication are mandatory. Exceeding
declared budgets, changed bytes, incomplete candidate scope, schema drift,
unknown candidate/domain, duplicate IDs or an existing output blocks publication.
SQLite staging and streamed source copies permit inputs larger than the metadata
limit. Generated fixed scripts embed only the reviewed converter and readers.

The plugin uses a pinned Python image, isolated networking, read-only root,
two CPUs and an 8 GiB container cap. Integration into a formally authorized
protected C workflow still requires the gate, lineage, family and method contract
acceptance for this entry point. A working network branch or a host test of this
node does not establish that acceptance. The matrix provides material for
scientific risk review; it is not the statistical `C_SAFETY` family result table.
