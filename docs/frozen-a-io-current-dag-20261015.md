## Repairs and bounded claim

Preflight requires five ordinary input files, existing destination parents, and
nine distinct fresh output paths. Existing files, directories, output aliases,
hard links and dangling symlinks are refused before truncating an old log or
running the method. The computation reads the same resolved input whose bytes
were checked, and input hashes are checked again before result publication.

The unchanged scientific body writes to owned same-parent staging directories.
A fresh diagnostic log is linked exclusively before calculation. The six TSVs,
RDS and provenance are exclusively linked only after calculation and input
rechecks. Each link is checked against the staged device/inode and SHA256;
all nine publications are checked again before success. This closes the earlier
counterexample where `file.link()` returned true but the destination had already
been replaced without an exception.

Caught-failure rollback removes only published scientific files whose recorded
device/inode and content still match. Foreign replacements and content-modified
destinations remain untouched. Directory cleanup checks the recorded staging
directory identity, and error-log append checks the owned log identity.

These are observed normal-exit/caught-failure and explicit fault-injection
guarantees, **not** a multi-file crash-atomic transaction, durable `fsync`
protocol, guarantee against adversarial concurrent path replacement, or a
resume/reuse certificate. SIGKILL/power loss can leave incomplete namespaces;
their existence is not successful completion. This work did not restart or
hot-install anything in the resident daemon.
