# CellChat 官方路线：产物保护与逐节点证据

## 选定方法及接口

本批对应候选 `cellchat_inference` 的既有严格替代路线
`cachexia_cellchat_official`，不是给旧包装器或全部 CellChat API 盖章。
固定官方 CellChat 2.2.0.9001、presto 1.1.0、R 4.4.1 和原 OCI digest；
包函数、数据库、13 个统计/读取辅助函数 AST 与冻结版本一致。
原先已由独立 R/C++ 源码构建完成的 11 个官方对照复用，不重装环境或重跑整套模型。

输入仍为完整 H5AD 和 20 键冻结 JSON；输出仍为结果表、完整 S4、audit、log、
细胞、基因、RNG/警告/合同状态、完整 DB×群对家族账本八个端口。
实际方法调用见固定 [CellChat 源码](https://github.com/jinworks/CellChat/blob/75253cd0c9e68410e6e721a6d3a0419a1d7e358f/R/modeling.R)。
细胞标签 bootstrap 不是供者级差异检验、循环到达、跨器官运输或因果证据。

## 已修工程缺陷

旧错误处理可删除已有分析文件、改写已有审计、追加已有日志。
八个端口逐一复现失败保护。修复后：

- 计算前拒绝已有路径、悬空链接及输入输出别名；
- 所有计算和诊断先写私有 staging；
- 使用排他硬链接发布，拒绝并发写入者；
- 回滚逐项核对本次创建的 dev/inode，不删除其他写入者的替换文件；
- 显式声明持久产物前缀，不把临时执行目录当作最终结果。

13 项实际 R 包装器保护测试通过；该测试明确使用库加载桩和无效合成合同，
不冒充官方算法数值验证。另有五项 canonical/adapter 声明与来源绑定检查。
排他发布和回滚不等于八个文件的文件系统事务，也不证明 SIGKILL 恢复。

## 当前 DAG、全对象与失败证据

使用已锁定 SDK 引擎 `4256643c55ae6fb50e8c867069330ed6ac2b4bc0`，
真实三节点/两边图运行严格适配器：两个 File 来源连接实际容器节点。
正常例八个端口全部发布并回读；完整 S4 除既有审计允许的 `options$run.time` 外
与冻结独立编译的作者参考完全一致，完整 RNG/警告/合同状态一致。
结果、细胞、基因及完整家族四张表逐字节匹配冻结版本；运行时间和完整对象均保留。
另有输入哈希错误、已有外来输出两条实际失败图，均无正常结果；外来文件保持原样。

开发中的验收器错误分别涉及不支持未执行旧节点的 baked argv、假定存在产物前缀、
遗留 TSV 诊断文件名。失败批次均保留，不能将整体非零退出改称通过。
完成的正例有独立记录的容器退出 0、完整对象比较退出 0、八端口及进度记录；
它来自后续因诊断复制错误失败的批次。补齐失败图并重新回读封存对象后，
单独的成功复核记录汇合证据；没有推断缺失成功退出，也没有再运行统计模型补绿。

## 仍不授予的资格

canonical 家族新增了相同严格节点，但旧 `cellchat_inference` 未修改、未认证；
真实 SDK 图使用严格适配器完整清单，不宣称旧 baked 分支或整个 canonical 家族运行通过。
当前生产加载、全新研究输入、完整 API/空间/合并/多 worker、全规模资源与恢复均不在本批范围。
家族账本不是多重校正，nboot 技术样例也不证明正式 P 值精度。
节点合同、来源/物种/尺度/对比资格仍须逐资源审核；无 G0 或科研签署。
