# 科研计算采用官方包：迁移边界与验收要求

依据用户要求，科研方法优先调用作者维护的 R/Python 包或官方命令行工具，
不再推进 Rust 原生统计重写，也不允许因官方后端失败而静默切回原生算法。
这是一项执行方向，不是已经覆盖所有生产入口的准入证书。

## 哪些代码仍需保留

- Rust 调度、类型化输入输出、资源约束、身份指纹与追溯属于工程层，不是统计方法替代品。
- 官方 API/数据集没有必须调用的统计包；可以保留 HTTP 客户端，但不能自行重算官方分数。
- 研究特定的资格检查、完整检验家族与失败传播没有对应的通用“官方科研包”。
  这些规则仍由方案适配层实现并独立验收，不能为了减少自有代码而删除。

## 已有路线不等于全部启用

统一仓库已有 TwoSampleMR、MRlap、singscore、UCell、lme4、limma/edgeR、
DESeq2、Scanpy 等官方包适配路线。存在源码或 manifest 不代表科学认证，
也不代表当前 daemon 已加载或研究合同已签署；必须查看各自的证据和适用范围。

普通回归的新增路线 `r_stats_lm` 调用 R Core `stats::lm`，不以 limma 或
lme4 偷换普通回归。其 R/stats 4.6.1 官方源码身份、接口及固定当前引擎的
46 个隔离 DAG 用例已有范围证明，见
[当前引擎证明](current-lm-engine-proof-20261014.md)。
该节点合同仍为 `TECHNICAL_ONLY_NOT_G0`；正式研究合同及生产部署未在该证明中授予。

`singscore_bspec` 的官方 1.32.0 路线也已补齐固定当前引擎的
[逐端口 DAG 与完整 RDS 对照](singscore-current-dag-20261015.md)：31 个 DAG、
另行直接验收的旧输出防覆盖、两类图构建拒绝，以及 10 份完整 RDS 和六类篡改反例。
这是限定输入与版本的技术证明，不代表真实队列、背景或生产部署已放行。

`h5ad_ucell_score` 已补齐官方 UCell 2.16.0 的
[当前引擎完整 H5AD 对照](ucell-h5ad-current-dag-20261015.md)：20 个正例、
34 个原始边界案例均已逐项归账，另有两类图构建拒绝。
它仅证明固定官方参数路线，不替代研究资源、成员映射、供者或部署审核。

独立 TSV 路线 `cachexia_ucell_official` 的官方包调用不变，但旧包装器的数据破坏
反例已复现并完成[路径保护与发布回滚修复](ucell-tsv-io-repair-20261015.md)。
12 个官方对象正例、一个 DAG 方法失败及 19 个路径／故障案例分别留证；
源码修复不等于生产插件已经更新，旧部署需先核验实际加载 revision。

`pseudobulk_counts → deseq2_de / limma_voom` 也有了
[三插件当前引擎连接证明](bulk-current-connected-dag-20261015.md)：两组固定普通／特殊
ID 样本核对全部 26 个 File 端口及独立官方结果；上游失败时不执行两条下游。
DESeq2 与 limma/edgeR 是直接官方包调用；机械计数聚合使用 SciPy，不能冒称运行了
仅用于独立对照的 Scanpy。真实研究资格与部署仍单独审核。

## 每个迁移节点必须分别完成

1. 明确官方方法、确切版本、输入尺度、统计单位、参数与输出含义。
2. 钉扎脚本、镜像 digest、参考资源与随机规程；拒绝不可核验的环境。
3. 在适配器之外运行独立官方参考，比较中间结果、数值、成员集合和失败状态。
4. 用真实声明端口连接固定引擎 DAG，回读落盘产物，验证错误不能发布成功结果。
5. 核对实际部署加载身份及冻结研究合同；技术通过不能代替科学签署。

官方包不能自动修正样本错位、错误协变量、缺失基因映射或不完整检验家族。
无合适官方实现、方法合同未批准或出现反例的分支继续挂起，不换名称冒充通过。
空间 B-S 仍为 `CONDITIONAL_NOT_READY`，GS01 仍为 OPEN；不自行选择置换零模型。

文献检索的 Rust HTTP 适配器也不能因调用官方服务而免验。
[Crossref 字段复核](literature-crossref-field-audit-20261015.md)发现空白字段可退化为无约束检索，
修复及 26 项 SDK/DAG 测试已实际通过，含 15 张拒绝图；严格 title 与 bibliography 的语义缺口单独保留，
不能用包装器守卫测试替代整条节点认证。

Open Targets 完整分页来源仍有重复成员反例。官方批量资源目前只完成
[资源与抽样 schema 审计](opentargets-bulk-metadata-20261015.md)，
尚未证明完整成员、字段映射或正式研究用途；不能自动替换冻结数据来源。

现已启动[完整直接关联及注释文件参照采集](opentargets-direct-source-acquisition-20261015.md)。
采集中的文件、请求守卫测试或软件锁元数据核查都不算节点放行；完成后仍需完整成员、
分数／novelty 语义、实际 DAG 和部署验证。上传模板与活跃项目的软件记录分开保留，
不得把不同版本或 counts/voom 与 normalized-array 方法混称为同一方案实现。

本文件不修改既有节点分母、276/288/696 检验家族、冻结配置、查看史或 G0。
