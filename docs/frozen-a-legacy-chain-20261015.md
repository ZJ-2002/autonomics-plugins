## Source execution repair

Review reproduced a time-of-check/reopen defect in the shared family
assembler's Python helper loader: hashing an input before a later
`SourceFileLoader` read did not bind the bytes actually executed. A final input
check could reject output only after unapproved source had already executed.

`family.py::helpers` now reads a bounded source buffer, checks its exact frozen
size and SHA256, then compiles and executes **that same buffer**. The three
original scientific helper definitions and the statistical/assembly function
ASTs are unchanged. The acceptance driver's own loader uses the same rule.
The regression includes the old vulnerable function and verifies that the
foreign-code counterexample is real, not merely a missing-output test.

official R reference: all three technical scenarios, 2,520 adjusted values,
and 18 complete RDS vectors. This replay uses the explicitly owner-bound
canonical alternate container store, not the production/default store.
